# 内核与 Schema 联动实测：2026-10-26

实现和验证使用本项目的本地工作区。在用户指定的 Docker 机器新建专属容器测试；原有 12 个容器未修改。官方 Mihomo 二进制版本为 v1.19.31、v1.19.32、v1.19.33。Schema 1.19.31、1.19.32 可获取，1.19.33 在本次测试时返回 404。

## 验证结果

前端 9 个测试文件、101 个测试通过，TypeScript 检查与生产构建通过。Go 后端测试编译为 Linux 测试二进制，在独立容器内全部通过。Windows 受限执行环境曾阻止测试临时文件的重命名；前端在正常文件权限下重跑通过，后端以 Linux 容器结果为准。

18 项自动化检查通过，包括：

- 首次安装 1.19.31，更新到 1.19.32，回退与再次切换；内核版本、Schema 版本和显式代理转发均符合预期。
- 1.19.33 对应 Schema 不存在时，保留 1.19.32 并返回明确警告；回退后警告随原版本一起恢复。
- 下载的二进制损坏被拒绝；Schema 包损坏不加载，改用旧版并警告；确认前暂存二进制被修改也会拒绝切换。
- 准备后配置变化会拒绝确认；非法协议配置被真实 `mihomo -t` 拒绝；原进程和 Schema 保持不变。
- 并发任务和陈旧当前版本标识返回 409。
- 候选启动期间主动终止候选进程，自动恢复原内核和 Schema，恢复后代理转发正常。
- 重启管理容器恢复已确认版本；切换过程中强制终止管理容器，重启后仍恢复最后确认版本。
- 工作区原文未修改；容器隔离及已有业务容器基线核对通过。

上述流程在最终后端代码上完整重跑通过。HTTP 转发仅访问内部受控源站，不代表公网节点或全部协议连接测试。

## 页面实测

通过临时 SSH 本机通道访问新容器中的生产构建页面，没有发布远端主机端口：

1. 预览显示内核与 Schema 的前后版本；取消后运行版本不变，确认后才执行切换。
2. 回退确认及回退后的真实版本显示正常。
3. 在保持同一个 Monaco 编辑器及未保存 YAML 不变的情况下，从 1.19.31 切到 1.19.32。新版新增字段 `tun.congestion-controller` 的非法枚举值立即显示第 5 行第 26 列诊断和合法备选值；切回 1.19.31 后诊断消失，文本未丢失。这验证了实际 Worker 校验规则的切换，而不只是版本标签变化。
4. 检查更新、选择版本、下载检查、预览和确认更新均通过页面执行。更新到 1.19.33 时，内核页面、预览对话框和 YAML 编辑器均明确显示保留的 Schema 版本及警告。
5. 临时 YAML 通过“放弃修改”恢复，未保存测试内容。核对远端工作区文件哈希未变，浏览器无相关错误日志。
