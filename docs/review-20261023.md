# 2026-10-23 代码审查与 Docker 实测

审查覆盖 YAML 解析与局部修改、节点/代理组/provider 引用、协议字段投影、保存预览、Go API 的状态持久化与请求边界、开发启动脚本和隔离测试工具。发现的问题已修复；当前仍是本地编辑器与运行模拟器，真实内核在单独的测试容器中运行。

## 修复的问题

| 级别 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | IP 规则含 `src` 参数时，简化编辑器保存会丢失该参数，改变源地址匹配含义 | 严格限定简化编辑器支持的规则形状，其余进入源码；列表显示按原生目标位置解析 |
| P1 | 节点改名漏掉子规则中的目标，且 `SUB-RULE` 的末项被误认为代理名；以 `src` 开头的代理名在后端被误判为参数 | 按规则类型确定目标位置，遍历主规则与子规则；区分子规则名称，保留 regex/逻辑表达式及尾部参数；补充子规则循环检查 |
| P1 | 后端未拒绝缺失 rule-provider、链式代理目标及节点/组混合循环，错误草稿可被模拟应用 | 增加后端结构及引用检查；错误草稿仍可保存，但模拟应用返回 422 且保留原运行状态 |
| P1 | API 只检查写请求 Origin，未限制 Host，存在 DNS rebinding 读取本地配置的入口 | 所有请求限制本机 Host，并检查携带的 Origin；本地浏览器正常工作 |
| P2 | DNS URL、隧道中的嵌入引用可能在改名/删除后悬空 | 检测这些消费者并阻止不完整改名/删除，提示在完整源码中一起修改；补上内联 provider 节点的链式引用 |
| P2 | 行内根映射的多个配置块共用一行，摘要行数会归错块 | 此类格式退回整份 YAML 的行数摘要，详细差异保留 |
| P2 | Worker 加载失败后重新连接 API，后续草稿仍投递给失效 Worker，可能一直显示解析中 | 终止失效 Worker，后续编辑使用同步解析回退 |

没有复制 GPL 项目的实现。规则目标位置和服务端字段以已固定的 Mihomo v1.19.32 源码为依据；表单继续复用已有 MIT schema 和 Apache-2.0 RJSF。

## 真机结果

最终完整一轮 **50 项通过**，使用用户提供的 Linux Docker 主机和官方 Mihomo v1.19.32。发布包大小、SHA256 与 GitHub release 元数据核对一致。每份协议客户端配置由管理器的编辑函数生成。

| 测试范围 | 实测结果 |
| --- | --- |
| TCP 转发 | HTTP、SOCKS5、VMess、VLESS TLS、Trojan、AnyTLS、Hysteria2、TUIC、VLESS WS/TLS、VLESS XHTTP/TLS、Shadowsocks，共 11 组 |
| UDP 转发 | SOCKS5、VMess、VLESS、Trojan、AnyTLS、Hysteria2、TUIC、Shadowsocks，共 8 组 |
| 转发路径证据 | HTTP/UDP 目标站同时检查标记、载荷和源地址，确认请求来自测试代理服务端，而不是客户端直连 |
| 原生资源 | 手动节点和订阅共存、订阅/规则集自动更新、HTTP/MRS/inline 规则、GeoSite/GeoIP DAT 下载解析与实际命中、GEO 手动更新 |
| 失败路径 | 损坏资源与 HTTP 503 保留旧资源；不存在的规则集被核心拒绝且重载失败后原配置可转发；错误 Trojan 凭据无法绕过代理，恢复正确凭据后恢复转发 |
| 改名 | 真实内核加载含子规则和 `src` 参数的代理组改名配置，继续正确转发 |
| Linux Go API | 实际运行编译后的管理器：保存不改运行状态、旧 revision 返回 409、错误引用模拟应用返回 422、恶意 Host 读取与跨站写入返回 403 |

首轮测试服务端没有为 VLESS 配置 TLS，内核日志拒绝启动三个 VLESS listener；客户端 `-t` 仍然成功。这是测试样本问题，已补齐服务端 TLS 并从全新目录完整重跑。它也说明 **配置检查成功不足以证明监听器启动或实际连接成功**。首轮失败和清理记录保留，没有计入最终通过数量。

TLS 测试使用本次生成的临时自签证书和测试客户端的 `skip-cert-verify`；证书信任链、Reality 握手、公网链路没有因此被验证。测试凭据均为固定的隔离样本，不使用用户真实订阅或节点。
